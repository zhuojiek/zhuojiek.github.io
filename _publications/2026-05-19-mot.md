<div class="tldr" markdown="1">
**The bet:** a unified model that is supervised to produce the image its own code renders to should get better at writing code for a target image, predicting what a program draws, and using code as an intermediate representation when it reasons about an image. The test is a matched-compute comparison against the same model trained on the same code with the image loss masked out.
</div>

## The gap

Models that emit graphics code (TikZ, SVG, matplotlib, manim, slide DSLs) treat the program purely as text. The model never observes what its code renders to, so any signal about visual fidelity has to come through a text-only proxy. Benchmarks like SGP-Bench, VIGA, and AutoPresent document the result: code that looks right and compiles, but renders to something else.

Unified models remove this restriction. In Chameleon, Transfusion, and BAGEL, image and text tokens live in one transformer with shared global attention, so an interleaved `<code>…</code><image>…</image>` sequence is a first-class training example. The renderer is deterministic, which means the supervision is exact and can be generated at scale.

## Setup

- **Backbone.** BAGEL 7B active / 14B total (a Mixture-of-Transformers), continued from the released checkpoint with its original joint loss: next-token on text, rectified flow on image latents.
- **Data.** TikZ is the primary domain because it renders deterministically and existing corpora (DaTikZ v2, arXiv sources) are large. SVG, matplotlib, manim, and python-pptx test cross-DSL transfer. Each program is rendered in a sandbox, deduplicated by AST hash and CLIP neighbors, and decontaminated against public evals.
- **Sequence mix.** About 70% prompt-conditioned full programs (`<prompt><code><image>`), 20% *render traces* where the program is chunked and the partial render is interleaved after each chunk, and 10% prompt-free `<code><image>` / `<image><code>` pairs. The traces are the visual analog of per-line execution traces in Code World Model: they give credit assignment between a local code edit and a local image change.
- **Baseline.** The same checkpoint continued on the same sequences with the flow loss on noised image tokens zeroed. The model still sees the images as context but is never supervised to produce them. This separates "image-side supervision helps" from "more code helps".
- **After mid-training.** A short SFT pass, then GRPO with a renderer-as-verifier reward: a compile check, CLIP image–image similarity, and a term for the failures CLIP underweights (text fidelity, fine geometry).

## Hypotheses

1. **Grounding.** (code, image) mid-training improves code-to-image generation over the text-only baseline.
2. **Understanding.** It also improves predicting what a program renders to.
3. **Transfer.** Mid-training on TikZ alone transfers to held-out SVG and matplotlib.
4. **RL initialization.** It makes the renderer-verified RL stage more sample efficient.
5. **Context unrolling.** The model can condition on its own intermediate renders to write better final code than single-shot generation.

## Ablations I care most about

- **Which expert does code go through?** BAGEL routes text through an understanding expert and images through a generation expert. Routing code through the generation expert instead tests whether code is representationally closer to text or to images. The MoT paper's PCA of modality clusters suggests this question has a real answer.
- **Sequence direction.** Code→image only vs. image→code only vs. mixed. My guess is that mixed wins on understanding because image→code forces the image to act as an input.
- **Natural vs. synthetic programs** at matched token count.
